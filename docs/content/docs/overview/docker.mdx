# Docker 部署

主 Compose 会启动 VenLinks 和 PostgreSQL 16。正式部署前先复制并修改 `.env`。

应用容器内部固定监听 `3000`，宿主机默认使用 `3002`，可通过 `.env` 调整：

```dotenv
VENLINKS_HOST_PORT=3002
```

Nginx 或宝塔反向代理应连接 `127.0.0.1:3002`。修改宿主机端口不会影响容器健康检查或 generation-worker。

## 安装

```bash
git clone https://github.com/csyqlz/VenLinks.git
cd VenLinks
cp .env.example .env
```

必填：

```dotenv
NEXT_PUBLIC_SITE_URL=https://venlinks.example.com
POSTGRES_PASSWORD=replace-with-a-strong-database-password
VENLINKS_ENCRYPTION_KEY=填写 openssl rand -hex 32 的输出
```

启动：

```bash
docker compose pull
docker compose up -d
docker compose ps
```

访问 `/install`，先确认只读连接检查，再点击“初始化表结构”并创建管理员。

## Compose 服务

```text
postgres -> PostgreSQL 16，数据卷 venlinks-postgres
app      -> VenLinks standalone，数据卷 venlinks-data
```

应用通过容器网络连接：

```text
postgres://用户:密码@postgres:5432/数据库
```

不要把 Docker 内数据库 Host 写成 localhost。

## 外部数据库与宝塔

外部 PostgreSQL 只启动应用，端口绑定在宿主机回环地址：

```bash
docker compose -f docker-compose.external-db.yml up -d
```

宝塔 PostgreSQL 通常监听宿主机 `127.0.0.1:5432`。此时使用：

```dotenv
DATABASE_URL=postgres://用户:密码@127.0.0.1:5432/数据库
```

```bash
docker compose -f docker-compose.baota.yml up -d
```

宝塔 Compose 使用 host 网络，只启动 `app`，不创建项目 PostgreSQL 容器。默认 Compose 和外部数据库 Compose 的 3000 端口也只绑定 `127.0.0.1`，由 Nginx 或宝塔反向代理对外提供 HTTPS。

宝塔单层 Nginx 反向代理默认使用 `VENLINKS_TRUSTED_PROXY_HOPS=1`，用于登录、生成和媒体访问的真实 IP 限流。接入 CDN 或额外代理时按可信代理层数调整；只有客户端直接访问应用时才设置为 `0`。

## 本地构建镜像

```bash
docker compose -f docker-compose.local.yml build app
docker compose -f docker-compose.local.yml up -d --no-build
```

本地构建 Compose 默认使用中国大陆可访问的 DaoCloud Node/PostgreSQL 镜像、npmmirror npm 源和阿里云 Debian 源，避免直接访问 Docker Hub、npmjs 和 Debian 官方源。需要使用私有镜像或其他区域镜像时，在 `.env` 覆盖：

```dotenv
VENLINKS_NODE_IMAGE=docker.m.daocloud.io/library/node:22-bookworm-slim
VENLINKS_POSTGRES_IMAGE=docker.m.daocloud.io/library/postgres:16-alpine
VENLINKS_NPM_REGISTRY=https://registry.npmmirror.com
VENLINKS_DEBIAN_MIRROR=http://mirrors.aliyun.com/debian
VENLINKS_DEBIAN_SECURITY_MIRROR=http://mirrors.aliyun.com/debian-security
```

构建阶段需要安装依赖并执行 Next.js 生产构建，建议至少 2GB 内存。低内存服务器使用发布镜像。更新已有部署时不要重新生成 `.env`，必须保留数据库密码、加密密钥和维护令牌。

## GitLab CI 部署

仓库根目录的 `.gitlab-ci.yml` 只响应 `dev` 分支的 push。每次 push 后会创建一个待手动执行的 `deploy_dev` 作业；其他分支以及非 push 流水线不会创建部署作业。

默认使用带有 `prod-docker` 标签的 GitLab Runner，并采用以下服务器目录：

```text
/home/workspace/VenLinks   # 持久源码构建目录，用于复用 Docker 缓存
/opt/1panel/apps/venlinks  # 部署配置目录，必须预先保存 .env
```

如果服务器目录不同，在 GitLab 项目的 CI/CD Variables 中覆盖 `SOURCE_DIR` 或 `DEPLOY_DIR`。两个目录必须预先创建并允许 Runner 用户写入，`DEPLOY_DIR/.env` 必须可读且保留已有数据库密码、加密密钥和维护令牌。

作业会把当前提交同步到 `SOURCE_DIR`，使用国内镜像配置构建 `venlinks:local`，然后让 Compose 根据新镜像更新 App 与 Worker 并等待整体健康检查；配置未变化的 PostgreSQL 容器不会被强制重建。命名数据卷不会被删除，已有 PostgreSQL 与媒体数据会继续保留。同一时间只允许一个 VenLinks 生产部署作业运行。

## 日志与检查

```bash
docker compose logs -f app
docker compose logs -f postgres
docker compose exec postgres pg_isready -U venlinks -d venlinks
```

安装页报数据库错误时，重点检查 `.env`、PostgreSQL 健康状态、数据库密码和 Host。浏览器只显示安全分类提示，完整连接错误保留在服务器日志。

## GHCR 权限

公开镜像可直接拉取。私有镜像需要登录：

```bash
echo "GitHub Token" | docker login ghcr.io -u GitHub用户名 --password-stdin
docker compose pull
```

Token 不得写入仓库或公开日志。

## HTTPS 反向代理

反向代理应保留 `Host`、`X-Forwarded-Proto` 和 `X-Forwarded-For`。站点地址使用真实 HTTPS 域名：

```dotenv
NEXT_PUBLIC_SITE_URL=https://venlinks.example.com
```

## 更新

使用发布镜像部署时：

```bash
git pull --ff-only
docker compose pull
docker compose up -d
docker compose ps
```

使用 `docker-compose.local.yml` 从源码构建部署时：

```bash
git pull --ff-only origin dev
docker compose -f docker-compose.local.yml build app
docker compose -f docker-compose.local.yml up -d --no-build
docker compose -f docker-compose.local.yml ps
```

如果部署的不是 `dev` 分支，请把第一条命令中的 `dev` 换成实际分支名。`build app` 会复用 Docker BuildKit 缓存，但缓存按文件内容判断：源码变化后，复制源码及其后的 TypeScript 检查和 Next.js 生产构建层会自动重新执行；依赖清单和锁文件没有变化时，依赖安装层仍会复用。因此正常更新无需每次禁用缓存，也不会因为复用缓存而继续运行旧应用代码。

构建成功后仍需执行 `up -d --no-build`，它会用刚构建的镜像重新创建 App 和 Worker 容器。只有怀疑缓存损坏或构建结果异常时才执行：

```bash
docker compose -f docker-compose.local.yml build --no-cache app
docker compose -f docker-compose.local.yml up -d --no-build
```

更新时不要覆盖已有 `.env`，尤其要保留 `POSTGRES_PASSWORD`、`VENLINKS_ENCRYPTION_KEY` 和 `VENLINKS_MAINTENANCE_TOKEN`。不要执行 `docker compose down -v`，否则会删除数据库和媒体数据卷；更新前应备份 PostgreSQL 和 `venlinks-data`。

## 数据卷

- `venlinks-postgres`：PostgreSQL 主库。
- `venlinks-data`：服务器媒体副本、文件模式数据和运行期文件。

Canvas、“我的素材”、短剧和工作台记录保存在 PostgreSQL，媒体位于 `venlinks-data` 数据卷。生产备份必须同时覆盖 PostgreSQL 与该数据卷。
